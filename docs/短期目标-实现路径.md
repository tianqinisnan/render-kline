# 短期目标：实现路径说明

本文档与当前仓库 `render-kline` 代码结构对齐，将「新功能、架构升级、多端适配」拆为可顺序落地的阶段。建议**严格按阶段顺序**推进：先完成数据与渲染分层，再叠副图与指标，最后做触摸与响应式，避免返工。

---

## 1. 现状基线（迭代前确认）

| 模块 | 路径 | 当前职责 |
|------|------|----------|
| 入口与配置 | `src/index.js` | 容器、参数、`init`、事件挂载 |
| 实例方法 | `src/proto.js` | `resetCanvas`、数据更新、缩放平移、loading |
| 主绘制 | `src/core.js` | 单一路径全量 `updateData` |
| 绘制原语 | `src/draw-tools.js` | 线、字、矩形、Y 轴、十字线等 |
| 事件 | `src/event.js` | 鼠标移动/拖拽/滚轮 |
| 常量 | `src/constant.js` | 价格字段名、边距、线宽等 |

**当前限制（短期要解决的）**：单 Canvas 全量重绘、无副图、无指标层抽象、无触摸、容器 resize 未系统处理。

---

## 2. 短期目标总览

1. **新功能**：成交量副图、多均线（及可扩展的指标插槽）。
2. **架构**：多 Canvas 分层、按层/按脏区减少重绘、`requestAnimationFrame` 合并刷新。
3. **多端**：Pointer Events 或 touch + mouse 统一、移动端滚动/缩放手势策略、基础安全区与 `meta viewport` 约定。

---

## 3. 阶段划分与详细步骤

### 阶段 A：数据层规范化（优先，1～2 天量级）

**目标**：后续副图与指标只依赖统一内存结构，避免字符串价格、字段不一致。

**步骤 A1 — 定义内部 K 线数据结构**

- 在 `src/` 新增 `src/model/`（或 `src/data/`）下的单一模块，例如 `normalize-bar.js`。
- 约定每条 K 线对 renderer 暴露为：

  ```text
  {
    time: number,      // Unix 秒或毫秒（全项目统一一种，建议在 normalize 内转秒）
    open: number,
    high: number,
    low: number,
    close: number,
    volume: number     // 无则 0
  }
  ```

- `updateHistoryQuote` / `pushQuoteInData` 入口处：将 API 原始对象 **映射** 为上述结构（保留 `constant.js` 字段名作为「外部 schema」配置也可）。

**步骤 A2 — 时间对齐与实时合并逻辑迁移**

- 将 `proto.js` 内 `pushQuoteInData` 中与 `TIME_INDEX`、`dataType` 相关的逻辑，改为只读写 **normalize 后的 `time`**。
- 补充单元测试（可选 Jest）：同一根 K 线内更新 close、跨周期新开一根。

**验收**：历史 + 实时数据在内存中全部为 number；画线逻辑逐步改为读 `bar.open` 等（或通过 adapter 保持旧索引访问，但推荐集中到一处）。

---

### 阶段 B：架构升级 — 分层 Canvas + 刷新调度（核心，3～5 天量级）

**目标**：主图与副图、静态与高频交互分离，为「局部渲染」打基础。

**步骤 B1 — 容器 DOM 结构**

- 在 `init`（`index.js`）中不再向 `cBox` 直接插入单个 `canvas`，改为插入 **包装层**，例如：

  ```html
  <div class="kline-root" style="position:relative;width:100%;height:100%;">
    <canvas class="kline-layer-grid"   />  <!-- 网格、Y 轴刻度背景（低刷新） -->
    <canvas class="kline-layer-main"   />  <!-- 蜡烛 + 主图均线 -->
    <canvas class="kline-layer-sub"    />  <!-- 成交量等副图（短期先一个） -->
    <canvas class="kline-layer-overlay"/>  <!-- 十字线、悬浮信息（高刷新） -->
  </div>
  ```

- 各 layer 使用 `position:absolute; left:0; top:0; width:100%; height:100%; pointer-events`：`overlay` 可 `pointer-events:none` 或仅 overlay 接收事件（见阶段 E）。

**步骤 B2 — 尺寸与 DPR**

- 抽象 `src/layers/resize-layers.js`（名称可自定）：根据 `cBox.clientWidth/Height` 与 `sharpness` 设置**所有** layer 的 `width/height` 与 style 尺寸（与现 `resetCanvas` 逻辑一致，避免重复代码）。
- 使用 `ResizeObserver` 监听 `cBox`，防抖后调用统一 `resizeAll()`。

**步骤 B3 — 刷新调度器**

- 新增 `src/scheduler.js`（或类 `RenderScheduler`）：

  - 对外提供 `markDirty(layerFlags)`、`requestDraw()`。
  - 内部用 `requestAnimationFrame` 合并一帧内多次 `markDirty`。
  - 短期可实现：`FULL`（全层重绘）与 `OVERLAY_ONLY`（仅 overlay：十字线）。

- 将 `event.js` 中 mousemove 从「直接 `resetCanvas` + `updateData`」改为 `scheduler.markDirty(OVERLAY)`；首次进入或数据变更用 `FULL`。

**步骤 B4 — 拆分绘制入口**

- 从 `core.js` 的 `updateData` 中拆出：

  - `drawGrid(ctx, state)` — 水平线、边距、与主图共享的 Y 轴区域（或主图 Y 在 main 层画）。
  - `drawCandles(ctx, state)` — 现有蜡烛循环（保留视口剔除）。
  - 副图区域预留：下方固定比例高度（如 20%）给 `sub` layer，主图占 80%（常量可配置）。

  **副图预留是做什么的？与代码进度对照**

  - **设计用途**：在主图 K 线下方留出一条独立的纵向区域，用于绘制与时间轴对齐的 **副图指标**（典型为 **成交量 VOL**，后续可扩展 MACD、KDJ 等占整条带宽度的指标），避免与蜡烛共用同一套价格纵向标尺。
  - **已实现（阶段 B）**：`constant.js` 中 **`SUB_CHART_HEIGHT_RATIO`**（默认 `0.2`）、`resize-layers.js` 内 **`mainPlotHeight` / `subPlotHeight`** 的计算；主图价格网格与蜡烛仅在主图高度内映射；**`sub` 图层 canvas 已存在** 并参与全量清屏与分层叠放。
  - **阶段 C 已补齐**：在 `sub` 层绘制成交量柱（`drawSubLayer` + `computeVolumeScale`）；其它副图曲线（如 MACD）仍待扩展。

- `proto.js` 的 `resetCanvas` 演化为：设置各层 context 的 transform / 默认 font，与 `state`（`movingRange`、`dataArr`、视口起止 index 等）只算一次。

**步骤 B5 — 局部渲染（短期可落地版）**

- **第一版**（建议先实现）：数据或缩放变化 → `FULL`；仅十字线变化 → 只清 overlay 层并重画十字线 + 读数（主图不 `clearRect` 全图）。
- **第二版**（时间允许）：主图在平移时仅 `drawImage` 位图块平移 + 只补边（实现复杂，可作为阶段 B 的「增强项」，不阻塞副图）。

**验收**：滑动十字线时 CPU 占用明显下降；resize 时各层比例正确、无模糊（与 `sharpness` 一致）。

### 阶段 C：成交量副图（2～3 天量级）

**目标**：在 `sub` layer 绘制与主图时间轴对齐的成交量柱。

**步骤 C1 — 布局常数**

- **`SUB_CHART_HEIGHT_RATIO`**：阶段 B 已接入（默认 `0.2`）；若需微调副图占比可改该常量；可选增加 `SUB_CHART_TOP_GAP` 等与副图内边距相关的常量。

**步骤 C2 — 比例与坐标**

- 主图 `core` 使用的 `centerSpace` 缩短，为副图让出 `subHeight`。
- 计算 `maxVolume` = 当前**可见**（或全量，短期可用全量简化）K 线的 `volume` 最大值，用于副图 Y 向缩放。

**步骤 C3 — 绘制**

- 在 `draw-tools.js` 或新文件 `src/draw-volume.js` 中实现 `drawVolumeBars(ctx, bars, xScale, subRect, colorUp, colorDown)`：x 与主图 `margin` 循环一致，颜色可与涨跌色一致或独立 `volumeUpColor` / `volumeDownColor`。

**步骤 C4 — 与数据流对接**

- `normalize-bar` 必须带 `volume`；`updateHistoryQuote` 合并后触发 `FULL` 重绘。

**验收**：切换 `blockWidth`、拖拽、缩放后，主图与成交量 x 对齐无漂移。

**实现备注（已与仓库同步）**：`computeVolumeScale` 见 `src/draw-tools.js`；副图绘制见 `src/core.js` 中 `drawSubLayer`；构造函数支持 `showVolume`、`volumeUpColor`、`volumeDownColor`（`README.md` 表格）。

---

### 阶段 D：多均线与基础指标插槽（3～4 天量级）

**目标**：主图叠加 MA5/MA10/MA20（可配置周期数组），并建立「指标」扩展点，为长期 MACD 等留接口。

**步骤 D1 — 纯函数计算层**

- 新增 `src/indicators/ma.js`：`computeMA(bars, period) => (number|null)[]`（与 `bars` 等长，前 `period-1` 位为 `null`）。
- 不放在 `draw` 里算，避免重复计算；在 `dataArr` 变化后算一次，结果挂 `this._series.ma5` 等，或统一 `this._computedIndicators`。

**步骤 D2 — 绘制**

- 在 `main` layer 蜡烛之后绘制折线：使用 `ctx.beginPath` + `lineTo`，颜色配置进 `options`（`maColors: string[]`）。

**步骤 D3 — 指标注册表（轻量）**

- 定义 `src/indicators/registry.js`：

  - `registerIndicator(name, { compute, drawMain?, drawSub? })`。
  - 短期只实现 `ma`；`drawSub` 预留给以后 MACD 在副图占高度。

**步骤 D4 — 与 Y 轴关系**

- 短期均线只使用**主图现有** `minPrice/maxPrice`（不调整价格轴）。若未来需要「仅按收盘价适配均线」可增开关；首版保持简单。

**验收**：改 `options.periods: [5,10,20,30]` 能出对应条数的线；数据追加时 MA 自动更新。

---

### 阶段 E：多端适配 — PC + 移动端（2～4 天量级）

**目标**：同一套逻辑在触摸设备可拖拽、双指缩放（或 UI 按钮缩放）、避免与页面滚动冲突。

**步骤 E1 — 统一指针事件**

- 优先方案：在 `canvas` 或 `kline-root` 上使用 **Pointer Events**（`pointerdown/move/up/cancel`），同时设置 `touch-action: none` 在图表区域，减少浏览器默认手势抢事件。
- 若需兼容极老环境，可保留 mouse 监听 + 补充 touch 事件委托到同一处理函数。

**步骤 E2 — 手势映射**

- **单指拖拽**：与现 `translateKLine` 一致，delta 换为 `clientX` 差值。
- **双指 pinch 缩放**（可选短期）：两指距离变化映射到 `scaleKLine` 的离散步进；首版可只做「+/- 按钮」或「双指 + ctrl 模拟」简化。
- **滚轮**：移动端无滚轮，依赖横向 drag + 可选工具栏缩放。

**步骤 E3 — Demo 与文档**

- `example/demo.html`：增加 `meta viewport`、去除未使用脚本；提供窄屏测试说明。

**验收**：iOS Safari / Android Chrome 上可横拖、十字线（若开启）可用单指移动模拟或长按（首版可仅 hover 桌面，移动上 overlay 跟手即可）。

**步骤 F1 — `destroy()`**

**步骤 F2 — README 与示例**

**步骤 F3 — 构建与 Lint**

## 4. 建议实施顺序（汇总）

| 顺序 | 阶段 | 说明 |
|------|------|------|
| 1 | A | 数据规范化，减少后续副图/指标返工 |
| 2 | B | 分层 + rAF + resize，为性能与副图腾空间 |
| 3 | C | 成交量副图（验证分层与 x 对齐） |
| 4 | D | 多均线 + 指标注册表雏形 |
| 5 | E | Pointer/touch 与 `touch-action` |
| 6 | F | destroy、文档、示例 |

---

## 5. 风险与依赖

- **副图与主图共用 `movingRange`**：所有 x 偏移必须在同一函数计算，避免复制公式。
- **全量重绘到局部重绘的过渡**：先保证分层与 `OVERLAY_ONLY` 正确，再考虑主图位图平移优化。
- **成交量极大时**：若卡顿，再在阶段 C 后增加「仅可见 range 求 maxVolume」。

## 6. 短期完成定义（DoD）

- [ ] 至少 4 层 Canvas（grid / main / sub / overlay）或等效职责分离。
- [ ] 十字线仅触发 overlay 重绘（数据未变时）。
- [ ] `ResizeObserver` 适配容器变化。
- [ ] 成交量副图与主图 x 对齐，配色可配。
- [ ] 至少 3 条可配置周期 MA，数据更新正确。
- [ ] 主流移动浏览器可拖拽浏览 K 线；PC 行为不退化。
- [ ] `destroy()` 可安全卸载实例。
